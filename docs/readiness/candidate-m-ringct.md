## Assessment for §2.2

Eligible on lines (a), (g), (h), (i) today. Lines (b), (c) need the exact review to be *performed* against `v0.18.5.1` (the E1 §2a controls apply here too, adapted to ringct/crypto rather than a zk gadget library); line (e) needs the BP+ audit read and every report URL pinned; line (f) needs each residual triaged. No line is **unknown**, so the record is completable without an external gate; the work is review effort, not waiting.

## Differences from the Ironwood record that matter for ADR-001

- No mechanized proof artifact (d) — assurance rests on audits, paper proofs and production history.
- No forward dependency on an unselected proof system; but a large **upstream rewrite (FCMP++)** is pending, which is a maintenance cost of a different kind: staying on 0.18.x freezes ring signatures (PLAN §7 caveat), following FCMP++ means re-doing this record for a new proof system.
- Incident class is implementation/economic (P2P, wallet, hashpower), not undetectable-counterfeiting-by-soundness-bug.
