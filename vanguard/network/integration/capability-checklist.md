## Lifecycle and independent acceptance

1. The future qualified adapter authenticates the immutable grant, exact committed source/inputs/artifact/bootstrap and review decisions. The current CLI refuses before this unavailable adapter.
2. The core opens only the existing original lock with NOFOLLOW/CLOEXEC, checks regular-file/owner/mode/link/device/inode, takes nonblocking exclusive flock and verifies its live kernel FD witness. It creates no lock inode and never explicitly unlocks it.
3. The existing manager retains the same open description and arms independent failure handling before acknowledging custody. A refused or lost admission cannot start provisioning. Its accounting starts with the attempt origin, including manager work under a qualified allocation.
4. A fresh first admission precedes O_EXCL ledger creation. File fsync then directory fsync must finish within the 5-second admission lifetime. Partial write, uncertain fsync or any existing receipt permanently consumes/refuses that grant; no reconstruction or retry.
5. Only after durable consumption may the manager provision the hard enclosure and import the immutable image. It returns observed context bound to the ledger and absolute deadlines. The core seals the private memfd and supplies only descriptors to the controller interface. A repeated, absent, stale, failed or late second admission cannot pass.
6. Failure, partial setup, timeout, controller crash or modeled OOM enters bounded recovery while the manager retains the lock. A Python finally block cannot survive SIGKILL or host OOM. That path remains the independently qualified manager's obligation; a synthetic manager is no host proof.
7. The core closes its copies after recovery handling and requests observation after its own exit. It can return only FAIL, refusal or PENDING_MANAGER_COMPLETION. Resource/cleanup rows remain NOT_RUN. Cleanup failures retain keeper custody for the manager's existing recovery path; they do not permit a successful receipt or grant retry.
8. The independent observer must verify all tracked task/recovery PID-start pairs absent, work/recovery population zero, exact CIDs/daemons/helpers/mounts/loops gone, allowlisted bounded export saved and all lock copies closed. Only then may it obtain the independent original-inode release witness and validate final completion. No observer is installed by this source.

Independent acceptance must challenge the kept guarantees rather than require loop/ext4 or a specific manager by name. It must also reject container-only caps, samples without disk enforcement, an observer killed with the workload, an outer that reports its own cleanup PASS, source-only tests offered as native OOM proof, a consumed grant retry, and unbounded manager/export/ledger writes. A later host test is authorized only by a separately exact grant. The native two-peer, wallet persistence, proof/maturity/payment and twelve-row matrix are unchanged and remain NOT_RUN.

No original heavy-lock access, host admission/capacity/resource polling, reservation, provisioning/install, image export/import, staging/build, container/native launch, shared-service change or launch occurs. ## Primary interface sources

The installed interpreter is Python 3.14.7. Versioned [Python os interfaces](https://docs.python.org/3.14/library/os.html#os.memfd_create) define memfd, descriptor non-inheritance, NOFOLLOW/exclusive opens, writes and fsync. [Python fcntl](https://docs.python.org/3.14/library/fcntl.html#fcntl.flock) defines nonblocking flock and file seals. The existing [kernel proc FD lock witness](https://docs.kernel.org/filesystems/proc.html#proc-pid-fdinfo-fd-information-about-opened-file) check is reused unchanged. [Kernel cgroup v2](https://docs.kernel.org/admin-guide/cgroup-v2.html) defines ancestor limits, delegation and subtree kill; killing the common parent also kills recovery inside it. [Python subprocess descriptors](https://docs.python.org/3.14/library/subprocess.html#popen-constructor) document explicit pass_fds, and [fsync directory durability](https://man7.org/linux/man-pages/man2/fsync.2.html) explains the separate parent-directory synchronization. These sources establish interface semantics. Installed manager support and host enforcement remain unverified.
