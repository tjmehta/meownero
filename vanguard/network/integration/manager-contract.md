## Consumption and crash/OOM custody

The operator reserves the exact grant/attempt/commit/input/artifact/bootstrap in a manager-owned slot and sends a fresh 32-byte activation secret only through a private inherited one-use channel. The slot contains its hash, not the secret. Sending that secret is not repeatable after an uncertain outcome. The manager cannot create, delete or rearm a slot. A new or restarted process with a RESERVED disk record has recovery-only authority; the record alone is never permission to consume or start again.

After the first full fresh admission, the manager overwrites the existing slot with QUARANTINED, fsyncs it and verifies its bytes before the outer may create a local receipt. Missing/corrupt slot, lost activation, partial write, fsync failure or admission expiry prevents local consumption and provisioning. An error burns the in-memory instance. A recovered manager never resumes setup even if a prewrite crash left RESERVED intact. Local O_EXCL/file/directory fsync remains useful but no longer carries the independent quarantine obligation alone.

The keeper must pass the original lock's same open file description to PID1 with FDSTORE and retain a live copy. The source supplies FD transfer plus a separate processing barrier. The helper must independently read back actual same-description custody before it acknowledges retain. A successful `sendmsg`, processing barrier, configured FD store or duplicate in one Python process does not prove custody survival. `FileDescriptorStoreMax=1`, preservation, retained namespace access and restart recovery need actual source/version/operator binding and later authorized host tests.

Use an empty aggregate parent capped at 2 CPU/4 GiB/no swap/256 PIDs. Work children receive at most 3840 MiB/224 PIDs and grouped OOM. Manager/helper/recovery/observer receive at most 256 MiB/32 PIDs in the recovery branch; their phases share this allocation. Killing the work branch must preserve keeper/recovery. The source does not attest that this split supplies sufficient headroom, PID1 overhead accounting, immunity from host OOM, or independent absolute deadlines. A common-parent OOM/kill must not be used as a recovery recipe. Systemd alone is not that proof.

At controller/launcher crash, timeout or work OOM, the surviving keeper enters recovery. At keeper death, PID1 must retain the FD and restart into recovery-only mode with the original absolute deadlines and namespace reference. The operator must establish an independently enforced end at origin+4500, including recovery/export, and a final observer after launcher/recovery exit. Recovery failure retains/quarantines custody and records failure; it never yields a success or makes the grant reusable. Power loss/reboot is failure and quarantine, not a same-open-description survival claim.

## Authenticated second admission and create

Use only unnamed inherited `AF_UNIX/SOCK_SEQPACKET` endpoints with `SO_PASSCRED`; authenticate each sender using `SCM_CREDENTIALS` and its PID/start identity. `SO_PEERCRED` on a pre-fork socketpair identifies the creator and cannot alone authenticate the later sender. Close unsolicited SCM_RIGHTS descriptors on rejection, reject truncation, bound messages to 64 KiB, use CLOEXEC, and enforce absolute send/receive deadlines.

Bind the endpoint request to grant/attempt/ledger/commit/input/artifact/bootstrap, exact create command and original-lock witness. Inspect/hash the image and prepare the exact create argv **before** observation. The helper consumes the request before any check, obtains a complete fresh memory/disk/load/process/container/original-lock observation, verifies the original FD again and invokes its own prevalidated create within five seconds. It returns a CID/observation, never a bearer admission token for later independent Docker create. Repeated, bad, stale, mismatched, incomplete or failed requests refuse permanently.

The legacy inner currently performs independent Docker create after its refusing admission seam. Wiring it to this atomic operation is a **remaining source integration**, requiring the exact authenticated helper binding; it is not delivered or enabled by this packet. This is why the new adapter refuses `run_controller` and qualification stays empty. No alternative authentication, network or private-RPC behavior is silently introduced.

## Primary interface evidence

The installed interpreter is Python 3.14.7; no installed systemd/helper version was newly inspected. [Python 3.14 socket messages and ancillary FDs](https://docs.python.org/3.14/library/socket.html#socket.socket.sendmsg) and [Linux Unix socket credentials](https://man7.org/linux/man-pages/man7/unix.7.html) define the local protocol. [systemd 255 FD store/preservation](https://www.freedesktop.org/software/systemd/man/255/systemd.service.html#FileDescriptorStoreMax=) and [notification barriers](https://www.freedesktop.org/software/systemd/man/255/sd_notify.html#BARRIER=1) define processing/custody mechanisms; they do not prove installation or accepted retention. [systemd mount namespaces](https://www.freedesktop.org/software/systemd/man/255/systemd.exec.html#PrivateMounts=) documents that separate ExecStartPre/ExecStart processes do not share a mount namespace, so preparation must not assume that topology. [Kernel cgroup v2](https://docs.kernel.org/admin-guide/cgroup-v2.html) defines hierarchical limits and work-subtree kill. [Docker dedicated daemon options](https://docs.docker.com/reference/cli/dockerd/) support private paths and disabled bridge/firewall options. [util-linux loop lifecycle](https://man7.org/linux/man-pages/man8/losetup.8.html) documents explicit device setup, sizelimit, nooverlap's find/reuse behavior and delayed detach. These primary sources were retrieved for this source delta; actual host compatibility remains unverified.
