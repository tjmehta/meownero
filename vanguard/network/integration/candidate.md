## Whole-attempt resource proposal and missing prerequisite

The container-only approach cannot enforce aggregate host work. Proposed replacement is one non-root cgroup-v2 domain parent with separate controller, dedicated Docker daemon and container children. Parent `cpu.max=200000 100000`, `memory.max=4294967296`, `memory.swap.max=0`, `memory.oom.group=1`, `pids.max=256`, empty direct cgroup.procs and active hierarchical controllers apply to all descendants. Account from before setup through export, Cargo copy, compile, native execution, archive, cleanup and service shutdown. Parent CPU usage must stay <=9000 core seconds, not just container counters. Kernel quota throttles CPU; it reserves no throughput. The dedicated daemon is required because existing shared-daemon work escapes a task cgroup. Moving or stopping the shared daemon or other workloads is forbidden.

All writable paths, including dedicated Docker data-root/exec-root/socket/logs, container metadata, Cargo copy, source archives, source/build, temporary files, private roots, public evidence and archive export must reside on one task-owned fixed-capacity filesystem <=15GiB. Container root is read-only, log driver none, no published ports/network none, writable /tmp and /out are binds into that filesystem. Toolchain is read-only. Image-store baseline usage counts toward15GiB. No tmpfs or anonymous writable volume escapes accounting. Backing filesystem admission is >=20GiB free, stop work below4GiB; the hard15GiB envelope is independent of sampling delay. Independent backing-disk watch and hard deadline must remain effective while controller operations block. No capacity feasibility is inferred from these limits.

Proposed load rule is all three load averages <=6.0 on the previously observed 12-logical-CPU host. This is a source-frozen proposal, not Platform approval or reservation. Admission also requires available memory>=5GiB, original device66306/inode657237/owner/mode0600/regular/no-symlink exclusive nonblocking lock and no native/compiler/container collision. The original inode must never be created, replaced, truncated or unlinked. Repeat fresh admission before any task provisioning and before workload container creation. Refuse immediately without polling, reserving, displacing workloads or lowering floors.
