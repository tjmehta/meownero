## Host constraints and gotchas (all learned the hard way)

1. **RAM is the binding constraint.** ~1–9 GB free; Chrome/Obsidian/openclaw hold the rest. Use `-j2` for C++ builds; `-j3` has been OOM-killed twice (exit 137). One heavy build at a time.
2. **No sudo, no apt.** Monero builds only in the Docker image. Zebra builds natively with `PATH=$SP/venv/bin:$PATH`, `LIBCLANG_PATH=$SP/venv/lib/python3.14/site-packages/clang/native`, `BINDGEN_EXTRA_CLANG_ARGS="-I/usr/lib/gcc/x86_64-linux-gnu/13/include"` (rocksdb bindgen needs gcc's builtin headers).
3. **`grep`/`rg` are shell functions here and misbehave in scripts** — use `/usr/bin/grep`. `sed -n "$L,$((L+20))p"` breaks when `$L` is empty; check first.
4. **`pkill -f <pattern>`** kills this shell if the pattern matches its own command line (exit 144). Use `pkill -x <name>` or explicit pids.
5. **The builder image has python3 but no curl.** Devnet RPC helpers use `urllib.request`.
6. **Devnet data dirs are root-owned** (written inside containers); `devnet.sh` clears them via a throwaway container.
7. **`monero-wallet-cli --password ''` is ignored** — it prompts and eats piped stdin. Use a real password. New wallets estimate their refresh height from the hard-fork table + clock; on a fresh chain use `monero-wallet-rpc` (`create_wallet`, `rescan_blockchain {"hard":true}`) rather than the CLI.
8. **Concurrent sessions share this working tree.** Three times, commits under TJ's identity from a parallel site-track session swept my staged files into their commit (`510ea61`, `500ff13`, `0c862c2`). Content survived each time. Commit early; consider `git worktree` if it keeps happening.
