## Defects found and fixed by these author checks

All of them were in the candidate before these fixes. QA should re-check them.

1. Plain QML `Text` was not exposed to AT-SPI, so body copy was unreadable. Fixed with `AText`.
2. Qt drops explicit accessible names on password fields. Fixed by also relating each field to its visible label (`Accessible.labelledBy`); Orca reads "Password password text".
3. `visible: false` subtrees (result banners, hidden buttons) stayed reachable. Fixed with effective-visibility `Accessible.ignored`; audited on eight screens.
4. Tab from a focused page heading jumped to the window start. Fixed: the heading joins the Tab chain while focused.
5. Picking a kit wallet destroyed and rebuilt the buttons, losing focus. Fixed with a stable model.
6. Checkable buttons were exposed as check boxes. They are now buttons that report pressed/checked.
7. Escape on the consent dialog cleared the pick. Per rev 5 it now only closes and returns focus to Connect; Keep clears the pick.
8. Definition rows read values twice. Inner content is now presentational.
9. Programmatic focus (dialog initial focus, focus return) showed no focus ring. Fixed.
10. Primary-button text rendered black: a QML property named `onNet` is parsed as a handler. Renamed.

## Known issues left for review

- Orca re-reads the whole dialog on every Tab inside the review dialog, which is verbose. The cause is unconfirmed, but Qt's popup focus events look like re-entry to Orca.
- A field error is spoken twice: once as the announcement and once as the focused field's description. The prototype did the same.
- The Space press on "Test wallet B" was not voiced as "pressed" by Orca, although the state is exposed. The field does fill.

## Proposed host-to-kit route (design only; connector stays disabled)

The handoff names three options (README handoff 2): a loopback-published port
with authentication, a mounted Unix socket, or a native node on the host.
TJS-1994 #4 forbids publishing container RPC ports, and #5 marks Unix-socket
RPC as unproven. Proposal for the next slice:

1. **GUI → AF_UNIX socket → in-kit relay → loopback wallet RPC.** The kit
   container stays `--network none`; its own loopback interface still exists.
   The kit runs `monero-wallet-rpc` bound to `127.0.0.1` inside the container,
   with fresh per-start Digest credentials (`--rpc-login`, never
   `--disable-rpc-login`). A minimal relay inside the container forwards one
   socket in a bind-mounted directory (0700, owned by the user) to that
   loopback port. A 0600 credentials file sits in the same directory.
   `SimulatedBackend` is replaced by a typed client over `QLocalSocket` that
   speaks HTTP Digest. It exposes only the allowlisted methods (tier A, plus
   `relay_tx {hex}` once verified) and reads the credentials file in C++;
   nothing reaches QML. Trust flags are passed explicitly.
2. **Prerequisites before any enablement:** execution evidence that the relay
   path works on the target host. On build-mac the kit runs inside a Colima VM, and
   AF_UNIX sockets across its shared filesystem are unproven and may not work.
   Also needed: evidence that the wallet `relay_tx {hex}` path relays the
   reviewed transaction, and acceptance of this exact boundary by the Wallet &
   Transport Privacy specialist. This mock adds no such boundary, so no privacy
   review was requested in this slice.
3. If the AF_UNIX path fails on build-mac, the remaining option is a native host
   node and wallet engine. That needs per-OS engine builds, which the handoff
   already lists as a later gate. Docker is not changed to make the mock look
   connected.

## Reproduce

```sh
source wallet-ui/env.sh && cmake -S wallet-ui -B wallet-ui/build -G Ninja -DCMAKE_BUILD_TYPE=Release && cmake --build wallet-ui/build
DISPLAY=:0 Xephyr :47 -screen 1500x800 -nolisten tcp &      # owned nested display
E=research/evidence/native-wallet-tjs2018-2026-10-10
$E/harness/run-journeys.sh wallet-ui/build $E 47
$E/harness/orca-journey.sh wallet-ui/build $E 47
$E/harness/measure.sh wallet-ui $E 47
```

The harness uses system `python3-gi`/`gir1.2-atspi-2.0`, `xdotool`, `ffmpeg`,
`Xephyr`, `orca` and `speech-dispatcher`, all already installed on this host.
It starts its own D-Bus session, AT-SPI bus and settings-portal stub. It
leaves the user's session bus, settings and audio untouched.
